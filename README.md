# 🦊 适用于早柚核心的OneBot适配器 (OneBotUID)

这是一个适用于 [早柚核心 (gsuid_core)](https://github.com/Genshin-bots/gsuid_core) 的 [OneBot v11](https://github.com/botuniverse/onebot-11) 适配器插件。它把实现了 OneBot v11 的协议端（NapCat / LLOneBot / Lagrange 等）接进早柚核心，把 QQ 消息转成早柚协议交给核心处理，再把核心下发的消息转成 OneBot 接口调用发出去。

## ✨ 主要功能

- **🔌 两种连接方式**: `WS客户端`（插件去连协议端的 WS 服务端）与 `WS服务器`（插件自己开 WS 服务端等协议端连进来）都支持，每条连接单独选。
- **🔀 多协议端**: `连接列表` 里加几条就是几个协议端，一个插件实例能同时挂多个 QQ 号。
- **📝 连接列表配置**: 每条连接独立配置地址、端口、Token、连接标识，可单独启用或禁用。
- **♻️ 热更新**: 改完配置不用重启，插件每 2 秒比对一次列表，只重启变更的那一条。
- **🛡️ 双向鉴权**: `WS客户端` 发 `Authorization: Bearer`；`WS服务器` 同时认 `Bearer` 头和 `?access_token=` 查询参数。
- **📡 元事件上报**: 支持向核心上报进群、退群、戳一戳三类标准 meta 事件。
- **↩️ 撤回回执**: 支持 `wait_recall` 场景，发送后回传 OneBot 消息 ID。
- **🛠️ 控制消息**: 支持核心下发主动撤回与群禁言/解禁控制。
- **🖼️ 图片外显**: 可配置发图时的 summary，多个文案用英文逗号分隔，发送时随机选一个。
- **🔄 断线重连**: 自动检测连接状态并重连，可设间隔与次数上限，也能用指令手动触发。
- **📊 状态监控**: 内置状态指令，只看**收到指令的那条连接**，含连接方式、在线时长与最近错误。
- **🧩 原生下发链路**: 复用核心的发送队列、日志回显、撤回回执，插件不重复实现一套。

## 🛠️ 安装说明

1. 把插件目录放进早柚核心的 `gsuid_core/gsuid_core/plugins/` 下，目录名保持 `OneBotUID`：

   ```bash
   cd gsuid_core/gsuid_core/plugins
   ```
   
   ```bash
   git clone https://github.com/xiowo/OneBotUID.git OneBotUID
   ```

2. 重启核心，插件会在 `on_core_start` 阶段自动开始连接。
3. 网页控制台 → 插件配置 → **OneBotUID**，按需填写 `连接列表`。


## 📝 配置指南

配置分两层：全局项由所有连接共享，`连接列表` 里每条记录对应一个协议端，可以随时新增 / 删除 / 单独禁用。

### 全局项

| 配置项 | 说明 | 默认值 |
| :--- | :--- | :--- |
| **启用适配器** | 总开关，关掉后所有连接都不启动 | `true` |
| **重连间隔** | 断线后等几秒重连 | `5` |
| **最大重连次数** | 最大尝试重连次数，0 为无限重连 | `0` |
| **回查引用正文** | 收到引用回复时调 `get_msg` 取被引用内容，关掉省一次调用 | `true` |
| **图片外显** | 发图时的外显文案，多个请用英文逗号分隔，发送时随机选择一个 | `空` |
| **合并转发 QQ** | 合并转发节点上显示的发件人 QQ，留空则用机器人自身 | `空` |
| **合并转发昵称** | 合并转发节点上显示的发件人昵称，留空则用机器人自身 | `空` |

### 连接列表（每条记录）

| 配置项 | 说明 | 默认值 |
| :--- | :--- | :--- |
| **名称** | 列表里显示的名字，留空用连接标识 | `空` |
| **启用连接** | 单独开关，关掉只停这一条 | `true` |
| **连接方式** | `WS客户端` 插件去连协议端 / `WS服务器` 插件监听等协议端接入 | `WS客户端` |
| **协议端 WS 地址** | `WS客户端` 模式下要连的地址 | `ws://127.0.0.1:3001` |
| **监听地址** | `WS服务器` 模式下监听哪个网卡，`0.0.0.0` 表示全部 | `0.0.0.0` |
| **监听端口** | `WS服务器` 模式下等的端口 | `3002` |
| **Access Token** | `WS客户端` 发 `Bearer` 头；`WS服务器` 校验协议端带来的 token；留空不鉴权 | `空` |
| **连接标识** | 这条连接在核心里的名字（`WS_BOT_ID`），**多条之间不能重复** | `OneBot` |
| **平台标识** | 上报消息时带的 `bot_id`，插件与数据库按它区分平台 | `onebot` |
| **忽略自身消息** | 协议端会上报机器人自己发的消息，开启后不再转发 | `true` |



## 📜 指令列表

命令前缀为 `onebot`，仅主人可用。

| 指令 | 描述 | 权限要求 |
| :--- | :--- | :--- |
| `onebot状态` | 查看**当前连接**的状态、连接方式、连接标识、平台标识、在线时长、连续失败次数、最近错误 | 主人 |
| `onebot重连` | 断开并重连**当前连接**；`WS服务器` 为断开协议端、等它重新接入 | 主人 |

> 「当前连接」指指令到达的那条连接，不会影响同核心下的其他连接。

## 🔌 协议端怎么配

以 NapCat 为例，在 WebUI 的「网络配置」里按插件选的连接方式加一条。

### `WS客户端`（插件去连）——协议端加「WebSocket 服务器」

| 配置项 | 说明 |
| :--- | :--- |
| 端口 | `3001`（按需修改，与插件里填的一致） |
| 消息格式 | `array`（必须是 array，CQ 字符串只能降级成纯文本） |
| Token | 可选，填了就要在插件配置里填一样的 |

插件默认连 `ws://127.0.0.1:3001`。

### `WS服务器`（插件监听）——协议端加「WebSocket 客户端」

| 配置项 | 说明 |
| :--- | :--- |
| URL | `ws://<核心所在机器IP>:3002`（端口对齐 `监听端口`） |
| 消息格式 | 同样是 `array` |
| Token | 填了就在插件里填一样的，协议端会放在 `Authorization: Bearer` 头里；也有协议端只支持拼查询参数，插件同样认 `?access_token=xxx` |

> ⚠️ **注意**: 如果协议端运行在 Docker 中，请勿将连接地址设置为 `127.0.0.1`，请使用宿主机 IP（如 `172.17.0.1`）或 Docker Network 容器名。核心在 Docker 里时，`监听地址` 要留 `0.0.0.0` 并把端口映射出去，否则容器外连不进来。

## ❓ 常见问题 (FAQ)

### Q1: 核心日志一直提示连接失败？
**A**:
1. 确认协议端的 WebSocket 服务器真的开了、端口对得上。
2. 协议端在 Docker 里时 `127.0.0.1` 指的是容器自己，换成宿主机 IP 或容器名。
3. 这个阶段插件还没注册到核心，所以核心侧不会出现这条连接；`onebot状态` 里会显示未连接和最近一次的错误原因。

### Q2: `WS服务器` 模式下协议端连不上来？
**A**:
1. 确认 `连接列表` 里的监听地址/端口是 `0.0.0.0:3002` 这种，协议端连的就是它。
2. 连不上多半是防火墙没放行、Docker 没映射端口。
3. 或者 `监听地址` 填了 `127.0.0.1`，那只监听本机，容器外连不进来。

### Q3: 能接多个账号吗？
**A**: 能，`连接列表` 里加几项就是几条连接，同一个插件实例即可。注意每项的 `连接标识` 不能重复，`WS服务器` 模式还要各占一个监听端口。
